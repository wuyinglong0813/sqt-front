# 2026-11-04 邀请弹窗与接收入口修复

后续已改为无需预填手机号的公开邀请，新增二维码、邀请码、链接及待实名/待审核权限隔离，配套迁移与发布要求见[2026-11-05 入企流程说明](../../sqt-backend/docs/member-invitation-onboarding-2026-11-05.md)。下文记录最初的弹窗问题排查。

## 线上核查

录屏中微信聊天已收到“邀请你加入商签通企业组织”的小程序卡片，点击后进入未加入企业的普通首页，没有邀请确认。通过用户授权的 SSH 连接，只读核查了生产数据库与 Nginx 访问日志，未修改生产配置或业务数据。

- 河北光屿行贸易有限公司向 `188****3419` 生成的成员邀请创建于北京时间 2026-11-04 16:17:09，有效期至 2026-11-05 16:17:09；核查时未使用。
- 对应账号在 16:16:39 完成手机号核验；个人实名认证状态为 `NOT_STARTED`，没有该账号的企业成员申请记录。
- iPhone 微信在 16:17:54、16:18:00、16:18:31、16:18:35、16:19:02、16:19:05 六次请求该邀请码的预览接口，均返回 HTTP 200；该时段没有提交加入申请的 POST 请求。
- 数据库邀请码与上述预览请求的 SHA-256 前缀均为 `d021ca`，确认属于同一邀请；不在文档中记录完整邀请码或登录凭据。

## 直接原因

未实名账号会进入成员邀请的实名引导分支。原 `confirmText` 为“去实名认证”；未核验手机号分支为“核验手机号”，两者均为 5 个汉字，超过微信弹窗确认按钮最多 4 个汉字的限制。

本机官方微信开发工具的 `WAService.js` 在调用原生弹框前，将非 ASCII 字符按双字节计算，确认按钮长度大于 8 即触发 `showModal:fail confirmText length should not larger than 4 Chinese characters`。从官方 SDK 抽取校验和回调实现进行离线验证，两段旧文案均未进入原生弹窗，只有 `fail` 与 `complete` 回调。原代码没有 `fail` 提示，所以用户看到普通首页且没有反应；`complete` 会执行，不能将原因描述为锁永久未释放。

本机官方 `lib.wx.api.d.ts` 及[腾讯接口文档](https://intl.cloud.tencent.com/zh/document/product/1219/68021)也注明按钮文案长度上限。线上成功预览、未实名状态和 SDK 校验复现共同指向这个直接原因；此次不能仅归因于重复打开被去重。

## 同时修复的入口问题

源码和本地生命周期测试还确认以下独立缺陷：

- 分享路径直接指向首页 Tab。首次打开并取消后，再次打开同卡片时，如果首页实例被复用，`App.onShow` 的相同场景/邀请码去重会忽略入口；没有新的首页 `onLoad` 来恢复邀请，最终只显示普通首页。
- 已成功处理的邀请码会在首页被本地历史记录静默清除，再次主动点击也没有结果提示。
- 新打开的链接若复用同码的旧认证续办对象，会继承上一账号的 `identityUserId`，随后被账号隔离逻辑清除。

## 改动

实名引导按钮改为“实名认证”，手机号引导改为“核验号码”，均为 4 个汉字。邀请确认弹窗增加失败提示，保留待处理邀请供重试；旧弹窗的失败回调不会干扰新打开的邀请。

成员与企业合作邀请改为 `/pages/invitation/invitation?inviteCode=…&type=…`，通过独立的非 Tab 页面承接。每次主动打开链接都创建新的待处理邀请，再切换到首页复用已有登录、手机号核验、实名认证、预览确认和申请流程。普通后台恢复继续保留原有去重逻辑。

显式打开已处理邀请时显示“邀请已处理”；缺少邀请码或跳转失败时在承接页说明原因，跳转失败可以重试。邀请参数仍只携带邀请码和类型，不携带完整手机号。领取资格和企业权限继续由服务端校验；本次无需后端改动或数据库迁移。

## 验证与发布

使用本机 Node.js 20 执行前端完整测试和主包源码体积检查。测试中的 `showModal` 按官方 SDK 的文案长度规则模拟参数校验：旧文案两项测试先失败，修复后通过。邀请回归还包括同一首页复用、取消后重开、普通恢复不重复提示、登录后续办、已处理反馈、账号隔离、弹窗失败与跳转失败重试及无效链接。完整测试日志位于 `/private/tmp/sqt-invite-front-tests-20261104.log` 和 `/private/tmp/sqt-invite-core-tests-20261104.log`。

最终验证：598 项 Node 测试、89 项核心回归及 12 项法人流程测试全部通过，共 699 项，其中邀请流程 40 项；主包源码为 1,347,095 字节，低于 1,500,000 字节预算。旧预览响应和旧确认回调不会覆盖新打开的邀请。

本次只修改本地源码，没有上传或发布小程序，也没有在接收人的微信真机上验证。发布后应重新生成并发送邀请卡片，以使用新的承接路径；已经发出的旧卡片仍指向旧首页路径。旧卡片可在彻底关闭小程序后重新打开排除当前进程的去重状态，但邀请有效期、号码和实名要求仍须满足。

真机验收需覆盖：未入企账号首次开卡、取消后再次开同卡、退出小程序后再次开卡、登录后继续申请、手机号核验及实名后返回、申请提交后再次开卡，以及管理员审核分配角色。
